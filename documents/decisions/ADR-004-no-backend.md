# ADR-004: 不做后端，纯静态托管

## Status

Accepted (2026-10-31)

## Background

Phase 0 已锁定：仅个人自用、无需注册登录、无后端用户体系。需明确论证是否真的不需要后端，以及不做后端的代价。

逐条核对"需要后端的典型理由"是否成立：

| 典型理由 | 是否成立 |
|---|---|
| 多用户数据隔离 | 不成立，单人自用 |
| 跨设备同步 | 不成立，场景是单手机"付款前看一眼" |
| 服务端计算 | 不成立，计算量 O(卡数×规则数)≈240 次算术，手机 <5ms |
| 卡规则库实时更新 | 不成立，规则跟随用户自己的卡 |
| 鉴权 / 计费 / 风控 | 不成立 |
| 敏感数据需保护 | 反向成立——无后端是更强的隐私保证 |

## Decision

**不做后端。Vite 构建为静态产物，托管于任意静态托管（Vercel / Cloudflare Pages / GitHub Pages / 本机）。**

不做后端是主动选择而非妥协：本产品的核心数据（卡库、账本）具有强隐私属性，**零网络请求**本身就是产品价值的一部分。

## Consequences

### 正面

- 零运维、零服务器成本、零数据库成本
- 零停机风险（静态资源 CDN 分发）
- 隐私最强：数据不出设备，无卡号，无外部上报，CSP 可设 `connect-src 'none'`
- 无鉴权实现成本，无会话/令牌刷新逻辑
- 交付最快：没有 API 契约、没有后端联调、没有部署编排

### 负面（必须向用户明示，不得隐藏）

1. **数据只存在于这台设备的这个浏览器**。换手机、换浏览器、清缓存 = 卡库与账本全丢。
   - 缓解：内建 JSON 导出 / 导入，**一期必做**（不是二期）

2. **iOS Safari 对未安装到主屏幕的站点，7 天未交互即清除脚本可写存储**。
   - 这是本项目第一风险。已在 ARCHITECTURE §4.2 详细记录。
   - 缓解：强制引导"添加到主屏幕" + `navigator.storage.persist()`（Chromium 有效，iOS no-op）+ 导出备份 + 静默清空检测

3. **无法跨设备查看**。用户若同时用 Mac 与 iPhone，需手动导出导入。
   - 可接受：核心场景是"掏手机付款前看一眼"

4. **卡规则不会自动更新**。银行改条款需用户自改。
   - 缓解：每条费率字段强制带 `sourceUrl` + `verifiedAt`，UI 显示核实日期，超 180 天提示过期

5. **没有崩溃上报**。线上出问题我看不到。
   - 缓解：计算引擎 100% 纯函数 + 单元测试锁定；运行时异常在 UI 显示可复制的错误详情，用户自行反馈

6. **无服务端恢复路径**。
   - 对比参考的通用 PWA 方案（保留服务端 cookie 认证的 re-hydrate 路径）在本项目不可用——没有服务端。因此防线只能落在"安装 + 导出"。

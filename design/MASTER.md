## 0. 一句话设计语言

**像一台精密的仪表，不像一个 App。** 打开就是能按的按钮和能读的数字，没有欢迎语、没有插图、没有 hero、没有入场动画。

**设计目标不是「好看」，是「让用户在收银台前 3 秒内做一个不需要后悔的决定」。** 所有取舍服从这一条：能少一次点击就少一次，能少一个字就少一个字，但**任何会误导用户相信错误数字的地方，宁可多写一行字**。

## 2. Token 全景表

> 完整值与用途见 `design-tokens.json`；对比度为脚本实算（WCAG 2.1 相对亮度公式），见 `tokens-reference.json`。

### 2.1 背景台阶（Surface）—— 层级靠色阶，不靠阴影

| Token | 值 | 用途 | vs surface-0 |
|---|---|---|---|
| `--surface-0` | `#0B0E14` | 页面底色 | — |
| `--surface-1` | `#11151D` | 答案卡、顶栏、TabBar、列表容器 | 1.12:1 |
| `--surface-2` | `#171C26` | 未选中段按钮、输入框底 | 1.32:1 |
| `--surface-3` | `#1F2532` | 选中段按钮、bottom sheet 本体 | 1.63:1 |
| `--surface-4` | `#2A3140` | popover、日期选择弹层（**全项目上限，不许再加层**） | 2.04:1 |
| `--row-champion` | `#1B2331` | 对比表冠军行整行底 | 1.16:1 vs surface-1 |
| `--row-hover` | `#181E29` | 对比表/列表行 hover | 1.09:1 vs surface-1 |

**台阶差刻意做小（1.1–1.3:1）。** 深色下台阶差一大就变成「一块块补丁」，界面立刻显廉价。

### 2.2 文字

| Token | 值 | 用途 | surface-1 | surface-3 | row-champion | 可用层约束 |
|---|---|---|---|---|---|---|
| `--fg` | `#E8ECF2` | 主文本 / 卡名 / 主角数字 | 15.42 | 12.94 | 13.30 | 全部 |
| `--fg-2` | `#B7C0CE` | 渠道行、解释句 | 9.96 | 8.36 | 8.60 | 全部 |
| `--muted` | `#8A94A6` | 字段标签、列头、币种符号、少赚差值、零净返 | 5.98 | 5.02 | 5.16 | **≤ surface-3**（s4 仅 4.26，禁用） |
| `--meta` | `#7D8798` | 核实日期、计数、来源域名 | 5.04 | 4.23 不达标 | 4.35 不达标 | **仅 surface-0/1/2** |
| `--disabled` | `#5A6274` | 禁用态 | 2.99 | 2.51 | 2.58 | 豁免（必带 `aria-disabled`） |
| `--on-accent` | `#FFFFFF` | accent 填充上的反白 | — | — | — | 唯一允许的纯白 |

**全部避开 `#FFFFFF` 做正文。** 近白（≈91%）长时间读金额不刺眼，且与纯白按钮形成自然分工。

### 2.3 语义色

| Token | 值 | 语义 | 使用条件（严格） | 对比度（s1） |
|---|---|---|---|---|
| `--pos` | `#3DD68C` | 省钱 | 净额 **> 0** | 9.75 |
| `--neg` | `#FF7A6E` | 亏钱 / 倒贴 | 净额 **< 0**（真亏钱才用） | 7.19 |
| `--muted`（复用） | `#8A94A6` | 少赚 / 零净返 / 未知 | 净额 ≥ 0 且非冠军；或 ±0.00；或未知 | 5.98 |
| `--warn` | `#E8B84B` | 警示 | 额度 ≥80%、优惠 ≤60 天到期、数据待核对、规则过期 | 9.91 |
| `--info` | `#6BA6F0` | 信息 | DCC 提示、来源说明、豁免生效说明 | 7.26 |

**「少赚」不新建色值。** 如果所有非冠军差值都用红，全屏一片红，红就失去信号价值（alarm fatigue）。全项目只有「真亏钱」配红。

### 2.4 强调色

| Token | 值 | 用途 | 关键约束 |
|---|---|---|---|
| `--accent` | `#2563EB` | **只做填充**：主按钮、FAB、选中态、Tab 指示条 | 做文字只有 3.54:1，**禁止**用于文字 |
| `--accent-hover` | `#2E6FE8` | 填充 hover（提亮，非压暗） | 白字 4.61:1 |
| `--accent-active` | `#1D4ED8` | 填充 pressed | 白字 6.70:1 |
| `--accent-text` | `#5B9DFF` | **文字 / 图标 / 当前 Tab / focus 环** | 6.71:1，所有台阶可用 |
| `--accent-tint` | `#12203A` | 选中行底、当前 Tab 底 | accent-text 于其上 5.96:1 |

**为什么主色是中性偏冷的蓝：** 绿已被 `--pos` 占用。主色与语义色同色 = 用户分不清「这是主按钮」还是「这是好消息」。蓝在本产品里不承载任何金额语义，只表示「可点 / 当前选中」。这是金融工具配色最干净的分工。

### 2.5 边框

| Token | 值 | 用途 | vs s1 |
|---|---|---|---|
| `--line-subtle` | `#232A38` | `divide-y` 行分隔 | 1.27 |
| `--line` | `#2A3140` | 控件边框 | 1.40 |
| `--line-strong` | `#3D4659` | 选中态描边、进度条轨道 | 1.93 |

边框只做边界暗示，不承担信息。控件的可辨识性由「底色台阶 + 文字标签 + 44px 形状」承担。

### 2.6 间距 / 圆角 / 字号 / 动效

| 类别 | 值 | 约束 |
|---|---|---|
| 间距 | 4/8/12/16/20/24/32/40/48/64 | 4px 网格，**禁止 5/7/13/15/22/30** |
| 圆角 | 4（徽章）/ 8（按钮输入）/ 12（卡片 sheet）/ pill | **卡片上限 12px**，不用 16+ |
| 字号 | 11 / 12 / 13 / 14 / 16 / 18 / 24 / **40** | 固定 rem，不做 fluid clamp |
| 字重 | 400 / 510 / 590 | 三级到底，不引入 700 |
| 字距 | 正文 `0` / 小字 `0.01em` / 全大写 `0.06em` / 40px `-0.02em` | 中文正文必须 0 |
| 动效 | 80 / 120 / **150** / **200**（答案）/ 220（展开）/ **400**（额度条上限） | 只动 transform 与 opacity |
| 缓动 | `cubic-bezier(0.2,0,0,1)` 默认 / `cubic-bezier(0.25,1,0.5,1)` 额度条 | 禁 bounce / elastic |

### 2.7 阴影 —— 深色下几乎无效的判断

**深色背景上阴影视觉增益趋近 0。** 在 `#0B0E14` 上叠 `rgba(0,0,0,0.3)` 是「更黑的黑」，看不出位移。

所以：
- 层级 = **背景色阶台阶 + 1px 边框**，`--elev-flat: none` 是所有卡片的默认
- `--elev-raised` 只给 3 处：**FAB / popover / bottom sheet 上缘**
- 其中的黑是「遮光」而非「投影」——深色下唯一有效的阴影语义

>  **如果照浅色主题习惯给每张卡片加 `shadow-md`，会得到一片糊，并吃掉所有台阶差，反而彻底失去层级。** 这是前端从浅色迁移过来最容易犯的错。

## 3. 组件规范

> 每个组件列出：结构 / 尺寸 / 八态 / 间距 / 文案。所有颜色必须引用 Token 名，**不允许出现裸 hex**。

### 3.1 SpendForm（消费输入表单）

主查询页的输入区。四个分区，全部**实时计算**，没有「查询」按钮（SPEC AC-F3-02）。

**结构（自上而下，间距 `--space-5` = 20px）**

```
[分区1] 消费地区   段按钮组 2 选 1（澳门 / 内地）        高 44px
[分区2] 消费类别   3 列网格 × 3 行（6 类 + 其他半宽）   每格 ≥44×44，gap 8px
[分区3] 金额       标签 + 输入框                        输入框高 56px
[分区4] 支付渠道   标签 + 横向滚动 pill 组               pill 高 36px / 命中 44px
```

**3.1.1 地区段按钮（`RegionSegment`）**

| 项 | 规格 |
|---|---|
| 尺寸 | 每个按钮 `flex: 1`，高 44px，圆角 `--radius-md` |
| 未选中 | 底 `--surface-2`，文字 `--fg-2`，1px `--line` |
| 选中 | 底 `--surface-3`，文字 `--fg` + 590 字重，1px `--line-strong` |
| hover | 边框 → `--line-strong`，120ms `--motion-fast` |
| focus-visible | 3px `--accent-text` 环 + 2px offset |

| disabled | 文字 `--disabled`，`aria-disabled`，`pointer-events: none` |
| 文案 | `澳门` / `内地`。**不写「中国内地」**——本产品用户就在澳门，「内地」是他们的日常说法 |

**3.1.2 类别选择器（`CategoryGrid`）**

| 项 | 规格 |
|---|---|
| 尺寸 | 3 列网格，`gap: var(--space-2)`，每格 `min-height: 44px` |
| 布局 | 图标 20px 在上、文字 13px 在下，竖向居中。**不用 emoji** |
| 7 个类别 + Lucide 图标 | 餐饮 `utensils` / 超市 `shopping-basket` / 加油 `fuel` / 机票 `plane` / 酒店 `bed` / 网购 `package` / 其他 `ellipsis` |

| 边界 | 类别名最长 2 字，不存在溢出。若未来加类别，允许 `nowrap` + 缩字号到 12px |

**3.1.3 金额输入（`AmountInput`）**

| 项 | 规格 |
|---|---|
| 结构 | 外层容器（底 `--surface-2`，1px `--line`，圆角 `--radius-md`，高 56px，左右 padding 16px）内嵌：币种前缀 `HK$`（16px / `--muted`，非大写） + 数字 input |
| 输入文字 | 28px / 590 / `tabular-nums` / `--fg` / 右对齐 |
| 标签 | 上方 12px `--muted`：`这笔消费多少` |
| 键盘 | `inputmode="decimal"`，`type="text"`（非 number：避免步进器与滚轮误触）。**不 autofocus**（iOS 禁止无手势聚焦，SPEC AC-F3-04） |
| default | 空。空态即引导（见 §8） |
| focus | 容器边框 → `--accent-text`，+ 3px `--accent-text` 环，offset 2px |
| error | 容器边框 `--neg`，下方 13px `--neg` 行 + `triangle-alert` 16px 图标 |

**3.1.5 表单整体纪律**

- 所有选填字段预填上次值，用户通常 0 次操作
- 输入防抖 200ms（防的是视觉闪烁，不是性能）
- 四个分区之间无边框、无卡片包裹，只靠 `--space-5` 间距分组。**卡片套卡片会让首屏变成一堆盒子**

### 3.2 AnswerCard（答案卡，sticky 底部）

**本产品唯一主角。** 全屏只有一个 40px 数字。

**结构（总高 180–200px，`--surface-1` 底，顶部 1px `--line`）**

```
┌────────────────────────────────────────────────┐
│ 刷这张                                  12px --meta │  ← 用用户的原话，不用「最优方案」
│ 汇丰 PULSE 银联双币钻石信用卡            24px/590 --fg │  ← 允许 2 行，clamp 2
│ [credit-card 16] 刷卡 · 澳门币结算       13px --fg-2  │
│                                                │
│ +HK$23.40                              40px/590 --pos │  ← tabular-nums
│ 净返 2.34%   ·   比第二名多 HK$12.80     13px --meta   │
│                                                │
│ ▁▁▁▁▁▁▁▁░░░░░░░░░░░░  已用 26%  剩 HK$1,960        │  ← 4px 额度条
├────────────────────────────────────────────────┤
│ 查看全部 7 张对比                          ▾   │  ← ghost 行，高 48px
└────────────────────────────────────────────────┘
```

**尺寸**：`position: sticky; bottom: var(--content-pad-bottom)`；`z-index: var(--z-sticky-answer)`；内边距 `16px 16px 12px`。

**八态**

| 态 | 表现 |
|---|---|
| **default（有结果）** | 见上图 |
| **empty（首次打开）** | **不显示骨架屏**。显示 12px `--muted` 引导 `选个类别和金额，立刻知道刷哪张`。40px 数字位**留空但保持高度**（`min-height` 锁死），保证 CLS = 0 |
| **empty（金额未填）** | 引导 `还差一个金额` + 一行 `输入这笔消费多少钱，答案就会出现在这里。` |
| **loading** | 仅当计算 >300ms 出现（正常不会）：40px 位显示 `——`（两个破折号，tabular 宽度稳定），**不转 spinner**（spinner 会让 3 秒目标显得更慢） |
| **error** | `读不到卡片数据` + 一行说明 + 主按钮 `重试`（内联重试，不刷新页面）+ 次级 `去导入备份` |
| **noResult（全部失格）** | `这几张卡本月额度都用完了` + 附次优解 `改用 X 卡可以拿 +HK$8.20` + CTA `查看额度`。**必须给次优解，不制造死路** |
| **allUnknown** | `这 7 张卡在这个类别都没有返现数据` + `不是它们不好，是我们还没查到。` + CTA `去补数据`。**绝不显示 -100% 或 0.00** |
| **edge（卡名超长）** | `-webkit-line-clamp: 2`，超出省略，`line-height` 固定避免高度跳 |

**数字排版（关键)**

- 币种符号 `+HK$` 用 **0.7em**（28px 时约 20px）且色 `--pos` 同色；`23.40` 用全尺寸 40px。视觉重量集中在数字上
- 符号 `+` 与 `−` **属于金额的一部分**，必须存在（SPEC §8 铁律）
- 净返率 `2.34%` 用 13px `--meta`，**不进 40px 位**——费率是手段，金额是答案
- 三者均 `tabular-nums`

**空状态为什么不用骨架屏**：骨架屏承诺「马上就好」，但这里不是加载慢，是用户还没输入。骨架屏会让用户等一个不会来的东西。

### 3.3 CompareList（对比表）—— 本项目最难的设计点

**怎么才能「不吵」？** 见下方专章 §4。此处只给组件规格。

**结构**：在 bottom sheet 内（`--surface-3` 底，顶角 `--radius-lg`，`max-height: var(--sheet-max-h)`）。

**列定义（4 列，固定宽度）**

| 列 | 宽度 | 内容 | 对齐 |
|---|---|---|---|
| ① 卡 / 渠道 | `flex: 1`，min 0 | 卡名 15px/510 `--fg`（clamp 1 行）+ 副行 12px `--meta`（渠道 · 外币费 x%） | 左 |
| ② 费率 | `56px` | 15px/510 `--fg-2` `tabular-nums` | 右 |
| ③ 净返 | `72px` | 15px/510 `tabular-nums`，`--pos`/`--neg`/`--muted` | 右 |
| ④ 差第一 | `64px` | 15px `tabular-nums`，`--muted`（少赚）/ `--neg`（倒贴）/ `—`（冠军） | 右 |

> 列宽合计 192px + gap。375px 视口下卡名列剩 375−32(gutter)−192−24(gaps) ≈ **127px**，可容纳 5 个汉字。**这是硬约束：卡名必须 clamp 到 1 行 + 省略号，不允许换行**（换行会让行高不固定，四列对齐立刻崩）。

**行态**

| 态 | 规格 |
|---|---|
| default | 行高 56px，`divide-y` 用 `--line-subtle`，无圆角、无卡片框 |
| **冠军行** | 整行底 `--row-champion` + 卡名 590 字重 + 行首 12px `--pos` 文字标签 `刷这张`（**不用奖杯 emoji，不用左侧彩色条纹**） |
| hover | 整行底 `--row-hover`，`--motion-fast`（仅 `@media (hover:hover)`） |
| active | 无额外反馈（行点开是内联 accordion，展开本身就是反馈） |
| focus-visible | 整行 3px `--accent-text` 环，`tabindex="0"`（行可键盘聚焦，可回车展开） |
| expanded | 行下方插入明细区（见下），背景 `--surface-2` |
| excluded（失格） | **独立分组**（见 §4.3），opacity `0.6`，行高 48px，无净返数值（数值位写原因） |
| empty | 不出现（有卡必有数据） |
| edge: 同名卡 | 卡名后追加 `（2）` 区分，不合并 |

**明细展开区（inline accordion）**

从行下方展开，用 `grid-template-rows: 0fr → 1fr` + `--motion-expand`（**不动画 height**）。

```
毛返现      餐饮 10%（Chill 商户）                        +HK$200.00
            来源 hsbc.com.hk · 2026-10-31              12px --meta
外币手续费  1.95%                                        −HK$39.00
            来源 bochk.com · 2026-10-31
月度上限    额外回赠 HK$150 已满，超出部分按 0.4% 计      −HK$50.00  ← --warn 图标
────────────────────────────────────────────────
净额                                                     +HK$111.00
回报率  5.55%
```

**每项必须带的元信息（SPEC AC-F4-02）**：来源域名（`--info`，可点，`SourceLink` 组件）+ 核实日期（`--meta`）。

### 3.7 ValidityBadge（时效徽章）

渲染 `ValidityState`（SPEC §5）。**这是最容易做得像报错的地方，必须克制。**

| state | 视觉 | 文案 |
|---|---|---|
| `permanent` | **不渲染任何徽章** | — |
| `active`（>60 天） | **不渲染徽章**，仅在详情内写 `优惠至 2026-12-31`（13px `--muted`） | `优惠至 2026-12-31` |
| `expiring_soon`（≤60 天） | 徽章：底 `--warn-tint`，文字 `--warn` 12px，左 `clock` 14px 图标，圆角 `--radius-sm`，padding `2px 8px` | `还剩 61 天到期` |
| `expired` | 徽章：底 `--neg-tint`，文字 `--neg`，左 `triangle-alert` 图标 | `优惠已于 2026-06-30 到期` |

**为什么必须克制：** 场景 3 的中银澳门全币种 0% 优惠 2026-12-31 到期，Today=2026-10-31 时 `daysLeft = 61`。**61 天不满足 `<=60`，因此此时是 `active`，不显示徽章**；2026-11-01 起才变 `expiring_soon`。

- 用 `--warn` 黄而不是红：**「快到期」不是错误，是提醒**。用红会让用户以为卡不能用了
- 不闪烁、不脉冲（SPEC §8 明令禁止）
- 不用感叹号 `!`、不用大写 `即将到期！`——感叹号是营销语言，不是仪表语言
- 如果同时有多个到期项，**只在最紧的那一项显示徽章**，其余进详情

### 3.9 ConfidenceTag（置信度标签）

**核心设计原则：区分「这张卡不好」和「我们不知道」。** 这两件事在视觉上必须完全不同。

| confidence | 列表 | 详情 | Token |
|---|---|---|---|
| `high` | **不显示标签** | 只显示 `2026-10-31 核实`（`--meta`） | — |
| `medium` | **不显示标签** | `数据来源：hsbc.com.hk，2026-10-31 核实`（`--info` / `--meta`） | — |
| `low` | 标签 `待核对` | 列出**具体哪项不确定**：`cap 上限口径有三个来源说法不一致` | 底 `--warn-tint`，字 `--warn` |
| `unknown` | 标签 `未知`；**数值位写「未知」** | `此项数据缺失。未参与排序。` | 底 `--line`，字 `--muted` |

**关键规则（SPEC AC-F1-03）：**

- `unknown` **绝不按 0 参与排序**。数值位显示文字 `未知`，不显示 `0.00`、不显示 `—`、不显示 `-100%`
- 若最优解涉及 `low`/`unknown`，**必须在结论下方显式提示**（SPEC AC-F4-03）：`这张卡此项数据待核对，结论可能偏差`（13px `--warn`）
- `high` 和 `medium` **不给徽章**。给徽章会让「正常」变成「值得一提」，全屏徽章 = 没有徽章

**为什么置信度不用 pos/neg 色**：用了会让用户把「没数据」读成「亏钱」。置信度是**知识状态**，不是**收益状态**，两套语义必须用两套视觉。

## 4. 对比表「不吵」的完整方案

这是本项目最难的设计点，单独成章。

### 4.1 为什么对比表容易吵

竞品 Cardli 的做法是每行塞 6–8 列（回馈率、下限、月上限、手续费、净回馈、备注），一屏阅读负担极重。我们的实测数据里单张卡就可能同时有：类别费率、渠道限制、月度上限、门槛档、外币费（还可能分项）、积分折算、置信度。**如果这些都进列，375px 屏幕上必然崩。**

### 4.2 四条规则

**规则 1：统一基准，只比一个数**

所有卡按**同一次消费的净返金额**计算。可横向比较的只有「净额」。禁止把 A 卡的费率与 B 卡的净额并排（苹果比橘子）。

**规则 2：恰好 4 列，列宽固定（不靠内容自适应）**

| 列 | 放什么 | 为什么放这里 |
|---|---|---|
| ① 卡 / 渠道 | 卡名 + 渠道 · 外币费 | 用户先要知道「是谁」 |
| ② 费率 | 该卡在这个类别的名义费率 | 因。用户想知道「它说给多少」 |
| ③ 净返 | 扣完所有费用后的金额 | 果。这才是答案 |
| ④ 差第一 | 与冠军的差额 | 用户不想自己算减法——这是本产品的核心价值（认知负荷转移） |

**列宽固定（56/72/64px）是关键**：固定列宽 → 行与行之间数字天然成列 → 眼睛扫一遍 72px 那条竖线就能比较所有卡。自适应列宽会让每行对齐都不同，等于没有表。

**外币手续费不进列。** 它是解释项，进明细 accordion。理由：用户关心「我拿多少」，不关心「为什么少」——但一旦他想知道，明细里必须有（SPEC AC-F4-02）。

**规则 3：冠军靠整行底色 + 字重 + 文字标签，不靠夸张装饰**

| 禁 | 有 |
|---|---|
| 奖杯 / 皇冠 emoji | 12px `--pos` 文字 `刷这张` |
| 左侧 3px 彩色条纹（AI 模板罪 #5） | 整行底 `--row-champion`（1.16:1 偏移） |
| 发光边框 / 阴影 | 卡名 590 字重（其余行 510） |
| 放大字号（会让列不对齐） | 净返数字加 `--pos` 色（其余行 `--fg-2`） |

**1.16:1 是实测值**：低于 1.12 看不出来，高于 1.25 会像「选中项」而不是「第一名」。

**规则 4：默认只展开前 3 名 + 失格卡独立分组**

- 第 4 名起折叠为 `展开其余 4 张 ▾`（48px ghost 行）。理由：一屏 5 行对比（约 300px）会把答案卡挤出可视区
- 失格卡（额度用尽 / 规则过期 / 无数据）**不进排名**，在末尾独立一组 `不推荐 · 2 张`
- **绝不让用户以为「这张卡没算进去」**——那是信任崩塌点

### 4.3 失格卡的处理（五态真实数据场景 5）

失格分两种，**必须视觉区分**，因为它们是完全相反的结论：

| 类型 | 含义 | 视觉 | 文案 |
|---|---|---|---|
| **「卡不好」** | 算得出，但结果差 | 正常行，`--neg` 数值 | `−HK$3.61` + 副行 `倒贴 HK$3.61` |
| **「我们不知道」** | 数据缺失 | 灰底标签 `未知`，**数值位写文字** | `未知`（**不写 0.00**） |
| **「卡不能用」** | 额度用尽 / 优惠过期 | 独立分组，opacity 0.6，`--warn` 图标 | `额度已用完（HK$5,000/5,000）` / `0% 优惠已于 2026-06-30 到期` |

### 4.4 用真实数据验证这套结构

以「澳门 · 餐饮 · MOP 2,000 · 刷卡」为例（数据来自 `data/cards-hk-mo.json`，汇率按 HKD 1 : MOP 1.03 折算，仅示例用）：

| 卡 / 渠道 | 费率 | 净返 | 差第一 |
|---|---|---|---|
| **中银香港 Chill** · 刷卡 · 外币费 1.95% | 10.00% | **+MOP 111.00** | — |
| 大丰银联双币钻石 · 云闪付 · 外币费 0% | 5.00% | +MOP 100.00 | −MOP 11.00 |
| BCM World Mastercard · 刷卡 · 外币费 0% | 1.00% | +MOP 20.00 | −MOP 91.00 |
| 渣打 Simply Cash · 刷卡 · 外币费 1.95% | 2.00% | +MOP 1.00 | −MOP 110.00 |

**算式（每一项都可复算）**

| 卡 | 毛返现 | 上限削减 | 外币费 | 净额 |
|---|---|---|---|---|
| Chill | 2,000 × 10% = 200.00 | cap HK$150 → −50.00 | 2,000 × 1.95% = 39.00 | 150 − 39 = **111.00** |
| 大丰 | 2,000 × 5% = 100.00 | cap MOP100（未触发） | 0（MOP 结算豁免） | **100.00** |
| BCM | 2,000 × 1% = 20.00 | cap MOP400（未触发） | 0（MOP 结算豁免） | **20.00** |
| 渣打 | 2,000 × 2% = 40.00 | 无 | 2,000 × 1.95% = 39.00 | 40 − 39 = **1.00** |

**这张表本身就在教用户三件事：**

1. **费率最高的不一定赚最多**：渣打 2% 只落 1.00，大丰 5% 落 100.00——因为渣打被 1.95% 外币费吃光
2. **名义 10% 实际只有 5.55%**：Chill 的 111.00 / 2,000。**这就是场景 2**，明细里必须写「额外回赠 HK$150 已封顶」
3. **冠军不是费率冠军**：Chill 费率第一且净额第一，但幅度远小于名义差距；若忽略 cap，Chill 会显示 +MOP 161.00（**虚高 45%**），且排名会退到第二——**这类错误必须被 cap 逻辑防住**

> **表中两个「差第一」是负数（−MOP 11.00）**：这是真实数据里最常见的形态——第二名与第一名只差 11 块。**「少赚」用 `--muted` 灰而不用红**，正是因为这种小额差距在对比表里出现频率极高，全染红会让整屏失去信号。

## 5. 数字排版铁律

这是省钱工具的生命线。数字排错了，产品就是玩具。

### 5.1 三级层级（只有三级，不搞四级）

| 级别 | 用途 | 字号 / 字重 | 格式 |
|---|---|---|---|
| **L-Answer** | 本次净返金额（唯一主角） | **40px / 590** | `tabular-nums` + 强制 `+`/`−` + 含币种符号 + 2 位小数 |
| **L-Stat** | 净返率、额度剩余、月度已用 KPI | **20–24px / 510** | `tabular-nums` |
| **L-Row** | 对比表 / 列表内的金额 | **15px / 510** | `tabular-nums` + **右对齐** |

**一屏只有一个 40px 数字。** 出现两个，就等于没有主角。

### 5.2 七条规则

1. **全部 `font-variant-numeric: tabular-nums` + `font-feature-settings: "tnum" 1`**。目标是「改金额时数字宽度不跳」——**这是信任问题，不是美观问题**。抖动会让用户觉得数字不可靠。
2. **金额列一律右对齐，标签列左对齐。** 中文用户扫读数字沿小数点/末位对齐。
3. **币种符号缩小到 0.7em 且用同语义色**。`HK$` 是上下文，`23.40` 是答案。视觉重量必须在数字上。
4. **符号属于金额，必须存在。** `+` 正、`−` 负（U+2212 真减号，不是连字符 `-`）、`±` 零。**这是无障碍的硬要求，不是风格选择。**
5. **小数位统一 2 位，不做「四舍五入到整数」。** 算错 1 块的可信度损失远大于多两位小数的视觉成本。**超过 10,000 才用千分位**。
6. **数字周围留白 = 文字周围 × 1.5。** 数字需要呼吸才显得「贵」。
7. **不用 monospace。** 等宽会让金额像代码，且字宽过宽浪费首屏横向空间。用 Inter 的 `tnum`。

### 5.3 正负零三态的完整规范

| 净返 | 展示 | 颜色 | 附加 |
|---|---|---|---|
| `> 0` | `+HK$23.40` | `--pos` | 无 |
| `= 0` | `±0.00` | `--muted` | 副行 `不赚不亏` |
| `< 0` | `−HK$4.20` | `--neg` | **副行必须写 `倒贴 HK$4.20`**（不靠颜色单独传达） |
| `unknown` | `未知` | `--muted` | 副行 `此项数据缺失` |

### 5.4 场景 1 的实现要求（渣打 Simply Cash 澳门刷 MOP）

这是产品最有说服力的教学样本，UI 必须让它一眼可见：

```
刷这张（假如此卡为冠军）
渣打 Simply Cash Visa 卡
刷卡 · 澳门币结算

+MOP 0.50                          40px --pos
净返 0.05%   ·   名义 2.00%，外币费 1.95%

▸ 为什么只有 0.05%                   ← ghost 行，引导展开
```

展开后：

```
毛返现        外币签账 2.00%                    +MOP 20.00
外币手续费    1.95%（HK 发卡 Visa 默认）         −MOP 19.50
             来源 sc.com/hk · 2026-10-31
渠道服务费    刷卡，澳门本地                      0.00
──────────────────────────────────────────
净额                                            +MOP 0.50
```

**设计要点：**
- 40px 位显示 `+MOP 0.50` 而非 `2.00%`（**金额是答案，费率是手段**）
- 副行的 `名义 2.00%，外币费 1.95%` 是**关键一行**：它让「2% 返现」和「0.05% 到手」在同一视野里，用户不需要点开就懂
- **如果这张卡不是冠军**，它的行里 `费率 2.00%` 与 `净返 +0.50` 并列，四列结构自然讲清逻辑——费率高的不一定赚得多

>  **数据一致性提醒（需 PM / 架构裁定）**：`data/cards-hk-mo.json` 里 `sc-simply-cash.categories.dining.rate = 0.015`（注释写「港币签账 1.5%」），而 SPEC §12 第 6.1 条断言「毛返现 2.0% → 净 0.05%」。**MOP 结算对 HKD 卡是外币，按数据只有 `flight/hotel` 行给了 2%，dining 行没有外币费率。** 若引擎按 dining 行取 1.5%，结果会是 `−0.45%` 而非 `0.05%`。这是 SPEC 验收标准与实际数据的真实冲突，**不是设计能修的**，需 PM/架构在实现前裁定（详见回传 advisory）。

## 6. 交互与无障碍

### 6.1 焦点可见（硬要求）

```css
:where(a, button, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: 3px solid var(--accent-text);
  outline-offset: 2px;
  border-radius: var(--radius-sm);
}
```

- **只用 `:focus-visible`**：鼠标点击不显示环（减噪），键盘/读屏 100% 可见。两件事可以同时做到
- `--accent-text` 在所有台阶上 ≥4.78:1，远超 3:1 要求
- **禁止 `outline: none` 无替代**
- 对比表的**行**必须 `tabindex="0"` 可聚焦（行可展开，是交互元素）

### 6.2 触控目标

| 规则 | 说明 |
|---|---|
| 最小 44×44px | WCAG 2.5.5。视觉可小（如 36px pill），**命中区必须用 `::after` 或 padding 撑满** |
| 相邻间距 ≥8px | `--space-2` |
| 行高 | 列表行 64px、对比行 56px、按钮 44px，全部 ≥44 |
| 图标按钮 | 视觉 20px 图标，容器 44×44（顶栏的 plus / trash / close 都是这种） |

### 6.3 键盘可达

| 交互 | 键 |
|---|---|
| 全部可点元素 | `Tab` 顺序 = 视觉顺序（DOM 顺序与视觉一致，不用 `tabindex` 正数） |
| 对比行展开 | `Enter` / `Space` |
| Sheet | `Esc` 关闭；打开时焦点移入 sheet 第一个可聚焦元素；关闭后焦点回到触发元素 |
| 抽屉/表单 | 不做焦点陷阱（除 sheet 外），但 `Esc` 关 sheet |

### 6.4 屏幕阅读器

| 元素 | 要求 |
|---|---|
| 金额 | `<span aria-label="净返 正 二十三块四毛">+HK$23.40</span>`。**符号必须被读出来**，视觉文本 `+HK$23.40` 对读屏是噪声 |
| 进度条 | `role="progressbar" aria-valuenow={pct} aria-valuemin=0 aria-valuemax=100 aria-valuetext="已用 96%，剩 100 港币"` |
| 图标 | `aria-hidden="true"`，语义由相邻文字承载 |
| 状态变化 | 答案卡外层 `aria-live="polite"`（不 `assertive`，避免打断） |
| 未知值 | 读作「未知」，不是朗读 0 |
| 图表/条 | 不用纯色传达，必带数字与文字 |

### 6.5 减少动效

`prefers-reduced-motion: reduce` → 全部时长 `0.01ms`（含颜色过渡），布局切换瞬变。用 `0.01ms` 而非 `0ms`：部分浏览器对 `0ms` 的 `transitionend` 不触发，依赖它的逻辑会挂住。

### 6.6 禁用组合表（**照做，别问为什么**）

| 禁止组合 | 原因 | 正确做法 |
|---|---|---|
| `--muted` / `--meta` 文本放 surface-3 以上嵌套 | 4.26 / 4.23，不达 4.5 | 换 `--fg-2`，或减一层嵌套 |
| `--accent` 做文字色 | 3.54:1 | 用 `--accent-text` |
| 卡片加 `shadow-md` | 深色下无效且吃台阶 | `--elev-flat` + 背景台阶 |
| 圆角 ≥16px 于卡片 | AI 过度圆滑 | `--radius-lg` = 12px 封顶 |
| `border-left: 2px` 彩色条纹做强调 | AI 模板罪 #5 | 整行底色 `--row-champion` |
| 数字滚动计数动画 | 拖慢 3 秒目标 | 直接显示终值 + 200ms 交叉淡入 |
| emoji 做功能图标 | P0-1 | lucide-react 16/20/24 |
| 渐变文字 / 渐变底 / 毛玻璃 | 全项目禁令 | 纯色 |

## 7. 布局与响应式

### 7.1 断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| mobile（主） | <640px | 单列，满宽 + 16px gutter，底部 TabBar，答案卡粘底 |

**移动优先，375px 起。** 桌面可访问但不做专门优化（SPEC §10）。

### 7.2 页面骨架

```
┌─────────────────────────────┐
│ 顶栏 48px + --safe-top       │  固定，不随内容滚动
├─────────────────────────────┤
│                             │
│ 可滚动内容区                  │  padding-bottom = TabBar + 答案卡高
│                             │
├─────────────────────────────┤
│ 答案卡（sticky，仅主查询页）    │  z-index 100
├─────────────────────────────┤
│ TabBar 56px + --safe-bottom  │  z-index 110
└─────────────────────────────┘
```

内容区必须预留 `答案卡高 + TabBar + safe-bottom` 的底部 padding，否则最后一行内容永远被遮住。

### 7.3 编号 section 禁令

**不给 section 加 `01 / 02 / 03` 编号，不给每节加小写大写追踪标签。** 那是 AI 脚手架的语法。本产品的分组标题只有两种：`澳门发卡` / `香港发卡` 这类事实性分组，和 `不推荐 · 2 张` 这类状态性分组。

## 10. Do / Don't

### Do

1. 答案卡永远粘底部拇指区，改金额时答案就在拇指上方跳动——这是本产品最爽的一刻
2. 所有金额 `tabular-nums` + 右对齐 + `+`/`−`/`±` 符号
3. 一屏只有一个 40px 数字
4. 失格卡显式说明原因（`额度已用完（HK$5,000/5,000）`），绝不静默排除
5. `unknown` 写「未知」，绝不按 0 排序、绝不显示 0.00
6. 空状态就是引导，不用骨架屏替代
7. 额度用「还剩多少元」表达，不只给百分比
8. 一个语义一个颜色：`--accent` 只表示可点，`--pos` 只表示赚，`--neg` 只表示倒贴，`--warn` 只表示将尽
9. 图标只来自 lucide-react，16/20/24 三档，`currentColor`
10. 动效 ≤400ms，只动 `transform`/`opacity`，尊重 reduced-motion
11. 层级靠背景台阶，不靠阴影

### Don't

1. emoji 作功能图标（P0-1）
2. 紫→粉渐变、Indigo→Pink 任意组合（P0-2）；`@theme` 里不许出现 purple/pink 色阶
3. `Welcome to` / `开启省钱之旅` / 任何营销语（P0-3）
4. hero 大标题、插图、3D 卡面、吉祥物、入场动画编排（P0-5）
5. 硬编码色值（一律走 Token，唯一例外 `#FFFFFF` 于 accent 上）
6. `border-left: 2px solid accent` 做行强调（AI 模板罪 #5）→ 用 `--row-champion` 整行底
7. `background-clip: text` 渐变文字
8. 装饰性毛玻璃 / 发光边框 / 渐变底色
9. 所有非冠军的差值都用红（红会失去信号价值）
10. 数字滚动计数动画
11. 卡片套卡片
12. `--accent` 做文字色（3.54:1 不达标）
13. emerald/绿色做主色（与 `--pos` 撞车）
14. 品牌 logo（支付宝/微信/云闪付/Apple Pay）→ 用文字标签 + Lucide 通用图标
15. 「查询」按钮（输入即算，没有提交动作）
16. 给 high/medium 置信度加徽章（会让「正常」变成「值得一提」）
17. 用红做「即将到期」徽章（那是提醒不是错误）

### 11.3 最容易做错的 6 处（按出错概率排序）

| # | 易错点 | 错误做法 | 正确做法 |
|---|---|---|---|
| 1 | **`--accent` 当文字色** | `color: var(--accent)` 做链接 | `color: var(--accent-text)`（6.71:1 vs 3.54:1） |
| 2 | **给卡片加阴影** | `shadow-md` 做层级 | `--elev-flat` + 背景台阶（深色下阴影无效） |
| 3 | **`unknown` 当 0** | 引擎/UI 把无数据当 0 显示 `0.00` | 显示文字 `未知`，不参与排序（SPEC AC-F1-03） |
| 4 | **忘记 `tabular-nums`** | 默认数字，改金额时宽度跳 | `.num` 类或 `font-variant-numeric: tabular-nums` |
| 5 | **对比表列宽自适应** | `flex: 1` 给所有列 | 卡名列 `flex:1`，其余 56/72/64px **固定** |
| 6 | **忽略 cap 直接显示标称费率** | Chill 显示 10% → +161（虚高 45%） | 先封顶再算，明细写「已封顶」 |

### 11.4 需要引擎配合的设计契约

| 设计需求 | 引擎必须提供 |
|---|---|
| 答案卡副行「比第二名多 X」 | `Scheme[]` 已排序，取 `[0].netRealistic - [1].netRealistic` |
| 「额度用尽后降为 X」 | `netRealistic` 与 `netOptimistic` 两个值（SPEC §6.3） |
| 明细逐项 + 来源 | `SchemeBreakdownItem` 带 `label` / `amount` / `sourceRuleId`，且能通过 `cardId` 查到 `SourceRef` |
| 「已封顶」提示 | `SchemeBreakdownItem.cappedBy > 0` |
| 失格原因文案 | `SchemeWarning` 的 `code` 映射到中文（见 §8.2） |
| 到期倒计时 | `ValidityState` + `daysLeft`（引擎算，UI 不自己算日期） |
| 置信度提示 | 卡片 `confidence` + 涉及的类别是否 `unknown` |

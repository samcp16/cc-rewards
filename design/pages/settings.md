# 页面：设置页 `/settings`

> 路由：`/settings`（TabBar 第 3 项）
> 关联：F7（导出导入）/ F11（安装引导 + 数据安全）/ 免责声明
> 基准视口：375 × 812
> 继承：`MASTER.md`。本文只写该页特有的 px 级布局

---

## 1. 这一屏承担什么

**这是本产品唯一「不解决决策问题」的页面**，但它承担两件比决策更要紧的事：

1. **数据存活**（F11，P0）：iOS Safari 对未添加到主屏幕的站点，7 天未交互即清除 IndexedDB。不安装 = 用户 8 张卡的规则在 7 天后静默消失。
2. **数据可带走**（F7）：零后端、零账号，导出 JSON 是唯一的备份手段。

**所以这一屏的语气必须是「认真的」，不是「随便看看的」。** 但同时不能吓人——用信息层级，不用红色警报。

## 3. 数据安全卡（置顶，最重要）

这一张**必须是唯一使用卡片形态的元素**，因为它是本页唯一需要用户「停下来读」的内容。其他都是可跳过的操作项。

```
┌─────────────────────────────────────────────────────┐
│ [shield-check 20 --info]                            │
│                                                      │
│ 你的数据不离开这台设备                                 │
│ 17px / 590 / --fg                                    │
│                                                      │
│ · 卡库和账本只存在本机浏览器里，没有任何上传          │
│ · 不存卡号、有效期、CVV                              │
│ · 没有账号，也没有后端服务器                          │
│ · 唯一会丢数据的情况：清浏览器数据，或 iOS 超过 7 天没 │
│   打开（安装到主屏幕可以避免）                        │
│                                                      │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 上次备份：7 天前            [立即导出备份]        │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器 | 底 `--surface-1`，1px `--line`，`--radius-lg`（12px），`padding: 16px`，**无阴影** |
| 图标 | `shield-check` 20px `--info` |
| 标题 | 17px / 590 / `--fg`，`margin-top: var(--space-2)` |
| 正文 | 4 条，14px / 400 / `--fg-2`，`line-height: 1.6`，`padding-left: 0` + `·` 前缀（不用 `<ul>` 的项目符号，中文字符对齐更稳） |
| 第 4 条 | **必须写「7 天」这个具体数字和条件**。写「可能丢失」等于没说 |
| 备份状态条 | 内嵌底 `--surface-2`，`--radius-md`，`padding: 10px 12px`，`display: flex; justify-content: space-between; align-items: center` |
| 备份状态文字 | 13px / 400 / `--meta`：`上次备份：7 天前` |
| **从未导出** | 状态文字改 `--warn`：`还没备份过` |
| **超过 30 天未导出** | 状态文字 `--warn`：`30 天没备份了` |
| 导出按钮 | secondary，高 36px（命中 44px），`立即导出备份` |

> **为什么安全声明不用 `--pos` 绿或图标打勾**：绿色在本产品只有「省钱」一个含义。用绿会让用户以为「安全 = 有收益」，也会稀释绿色的唯一性。用 `--info` 蓝：它表示「说明性信息」，与「可点击」的 accent 区分开。

## 4. 安装到主屏幕（F11，P0）

### 4.1 入口行

```
  ┌───────────────────────────────────────────────┐
  │ [smartphone 20 --accent-text]                 │
  │ 安装到主屏幕                            ›      │  高 64px
  │ 避免 iOS 7 天后清掉你的卡库                    │  13px --warn
  └───────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 行高 | 64px，底 `--surface-2`，1px `--line`，`--radius-md` |
| 图标 | `smartphone` 20px `--accent-text` |
| 主文字 | 15px / 510 / `--fg` |
| 副文字 | 13px / 400 / **`--warn`** ← 唯一一处行内黄字，因为它确实关系数据存活 |
| 右侧 | `chevron-right` 16px `--muted` |
| **已安装时** | 整行替换为 `[check-circle-2 20 --muted] 已安装到主屏幕`（13px `--meta` 副文字 `数据不会因为 7 天没打开而被清除`），**不再是可点行、不再有箭头** |

> **判断「已安装」**：`window.matchMedia('(display-mode: standalone)').matches || navigator.standalone === true`。这不属于设计范围，但必须由前端实现——**如果按 UA 判断 Safari，会把「已在主屏幕打开」误判成「未安装」**，导致用户反复看到安装引导。

### 5.2 导出（AC-F7-02）

点「导出备份」→ 立刻生成并下载，**不弹确认**（导出是只读操作，无风险）。下载后 Toast：`已导出，文件名 shuanazhang-2026-10-31.json`。

**导出内容说明**（如需展开，用一个 16px 提示行）：`包含 8 张卡和 214 条账本记录。不包含任何卡号。`

### 5.3 导入（AC-F7-03 / AC-F7-04 / AC-F7-05）

**这是本页唯一需要多步的流程。** 三种失败必须各有独立文案。

**步骤 1：选择文件**

```
从文件 App 选择之前导出的 JSON 文件。
[选择文件]   ← 主按钮 44px
```

**步骤 2a：格式错误（AC-F7-03）**

```
┌──────────────────────────────────────────────────┐
│ [triangle-alert 20 --neg]                        │
│ 这个文件不是刷哪张的备份                           │
│                                                   │
│ 缺少字段：cards[0].fxFee.rate, ledger             │
│                                                   │
│ 现有卡库没有改动。                                 │
│                                                   │
│ ┌───────────────────────────────────────────────┐│
│ │ 换一个文件                                     ││  主按钮 44px
│ └───────────────────────────────────────────────┘│
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器 | bottom sheet，`--surface-3`，顶角 12px |
| 图标 | `triangle-alert` 20px `--neg` |
| 标题 | 18px / 590 / `--fg` |
| **字段列表** | 13px `--font-mono` / `--neg`，底 `--surface-4`，`--radius-sm`，`padding: 8px 12px`，可换行 |
| 收尾句 | 14px / 400 / `--fg-2`：**`现有卡库没有改动。`** ← 必须有，这是用户最担心的 |
| 按钮 | `换一个文件`，主按钮 44px |

> 字段名用 monospace 是**唯一允许 mono 的地方**（MASTER §2.6）。因为这是路径不是金额，mono 能帮用户对上 JSON 里的位置。

**步骤 2b：冲突（AC-F7-04）**

```
┌──────────────────────────────────────────────────┐
│ 发现 2 张同名卡                                    │
│                                                   │
│ 中银香港 Chill 信用卡                              │
│ 渣打 Simply Cash Visa 卡                          │
│                                                   │
│ 选「覆盖」用文件里的版本替掉，选「保留两者」会存成   │
│ 两张，名字后面加「（导入）」。两种都不会丢数据。      │
│                                                   │
│ ┌───────────────┐ ┌───────────────┐             │
│ │  保留两者      │ │ 覆盖          │             │  ← 并列，等宽
│ └───────────────┘ └───────────────┘             │
│              取消                                 │  ← ghost 全宽 44px
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 同名卡列表 | 每张 13px / 400 / `--fg-2`，前缀 `· `，`clamp 2 行`。**必须列出具体是哪几张**，只写数量会让用户不敢点 |
| 说明文案 | 14px / 400 / `--fg-2`，**必须解释两个选项各自的结果** |
| 按钮排布 | `保留两者` / `覆盖` 并列等宽（各自 `flex:1`，gap 8px），`取消` 独立全宽 ghost |
| **`覆盖` 的视觉** | secondary 样式（透明底 + 1px `--line-strong`）。**不用 destructive 红**——覆盖不是删除，账本按 id 去重合并，不丢数据 |
| **默认焦点** | 落在 `取消`（最安全项）。键盘用户按 Enter 不会误覆盖 |
| 按钮顺序 | `保留两者`（左）在前，`覆盖`（右）在后。**破坏性更强的放右边**（从左到右递减安全度） |

**步骤 2c：写入失败（AC-F7-05）**

```
┌──────────────────────────────────────────────────┐
│ [rotate-ccw 20 --neg]                            │
│ 导入没完成                                         │
│                                                   │
│ 写入时出错了，已经全部撤回。你原来的卡库还在，         │
│ 和导入前一模一样。                                 │
│                                                   │
│ ┌───────────────────────────────────────────────┐│
│ │ 重试                                           ││
│ └───────────────────────────────────────────────┘│
│              取消                                 │
└──────────────────────────────────────────────────┘
```

> `已经全部撤回。你原来的卡库还在，和导入前一模一样。` —— **整句必须说清「整体回滚」的结果**，而不是技术词「事务已回滚」。用户不关心事务，只关心他的数据还在不在。

## 6. 显示设置

### 6.1 计入积分价值

```
   计入积分价值                        [switch 开]
   关掉后只算现金回赠，积分卡会显示「未计入」  13px --meta
```

| 项 | 规格 |
|---|---|
| 行高 | 64px |
| 标签 | 15px / 510 / `--fg` |
| Switch | 44×26 轨道，20px 圆钮；开 `--accent` / 关 `--line-strong`；命中区 44×44 |
| **必须有文字标签** | 纯 switch 无标签是不可接受的（无障碍 + 可用性双重问题） |
| 副文字 | 13px `--meta`，说明关掉后的后果 |
| 语义 | `role="switch" aria-checked` |

> 这一项对应 `ValueParams.includePoints`（ARCHITECTURE §3.6）。**关掉后积分卡不显示 0%，显示「未计入」**——否则用户会以为这张卡没有返现。

### 6.2 积分估值

```
   积分估值                        HK$0.005 / 分  ›
   按 yuu 200 分 = HK$1 折算        13px --meta
```

| 项 | 规格 |
|---|---|
| 值 | 15px / 510 / `--fg-2`，`tabular-nums`，右对齐 |
| 副文字 | 13px `--meta`，**必须给出折算依据**（不是随便填个值） |
| 点击 | 进入小 sheet：数字输入 + 3 个预设（`yuu 0.005` / `MR 未知` / `自定义`） |
| **`MR` 显示「未知」** | Amex `pointsValuation.valuePerPoint = null`。UI 必须写 `值未知`，不填 0（MASTER §3.9） |

## 8. 空 / 错误状态

| 场景 | 表现 |
|---|---|
| 存储申请被拒（AC-F11-02） | 数据安全卡下方加一条 `--warn-tint` 带：`浏览器没给持久化存储权限。请务必安装到主屏幕，并定期导出备份。` |
| 从未导出过 | 备份状态条 `--warn`：`还没备份过` + 按钮 `立即导出备份` |
| 导出失败 | Toast `--neg`：`导出失败，浏览器可能不支持下载文件。试试用「分享」把页面存下来。` |
| 数据被清空（F11 静默清空检测） | **首屏就拦**（不在设置页）：`你的卡库不见了`（20px/590）+ `这台设备上的数据被浏览器清理了。如果你导出过备份，现在可以导入。`（14px `--fg-2`）+ 主按钮 `导入备份` + ghost `重新开始`。（此状态由主查询页或启动层呈现，此处仅记录文案归属） |

# 页面：（引导层）iOS 安装引导

> 路由：非独立路由——以 **bottom sheet 覆盖在任意页之上**（首屏 / 设置页入口）
> 关联：**F11（P0）**：AC-F11-01 / AC-F11-02 / AC-F11-03
> 基准视口：375 × 812
> 继承：`MASTER.md`。本文只写该层特有的 px 级规范

---

## 1. 为什么这是 P0 而不是「引导页」

**iOS Safari 对未「添加到主屏幕」的站点，7 天未交互即清除 IndexedDB。** 四个独立来源交叉确认（ARCHITECTURE §4.2）。

所以这不是「引导优化」，是**用户数据能否存活**的前提。用户花 20 分钟录入 8 张卡的规则，7 天不开，全没。

**设计上必须做到三件事：**

| 要求 | 设计手段 |
|---|---|
| 让用户看懂后果 | 直接说「7 天后会消失」，不用「建议安装以获得更好体验」 |
| 让用户当场就能做完 | 分步骤、标出 Safari 里的具体按钮位置、每步一句话 |
| 不烦人 | 可关闭、可稍后、**不当模态墙**（用户可以先做题再安装） |

## 2. 触发逻辑（设计契约，前端实现）

| 时机 | 表现 |
|---|---|
| 首次访问，iOS Safari，未安装 | 进入主查询页 **8 秒后**（不是立即）弹 sheet。立即弹会打断「第一次看到答案」的关键时刻 |
| 用户关闭过 | **24 小时内不再自动弹**（`localStorage` 记 `installPromptDismissedAt`） |
| 用户已关闭 3 次 | 不再自动弹，只在设置页保留入口 |
| 已是 standalone 模式 | 永不出现（判断：`display-mode: standalone` 或 `navigator.standalone`） |
| 非 iOS | 不出现（Android 有 `beforeinstallprompt`，走原生安装，不需要此引导） |
| 非 Safari（iOS 上的 Chrome / 微信） | 出现，但**第一步是「换用 Safari 打开」**——iOS 上只有 Safari 能添加到主屏幕 |
| 从设置页入口进入 | 立即出现（用户主动要求，不受 8 秒与 24 小时限制） |

> **8 秒这个值是设计决策不是技术常量。** 依据：本产品「打开即出答案」，用户在前 3 秒读答案、接下来 5 秒可能改个金额。8 秒后他已经完成第一次核心体验，此时提示安装是「他刚觉得有用」的时刻，接受率最高。过早 = 干扰，过晚 = 他已经关掉了。

## 4. 步骤行规格

```
┌─────────────────────────────────────────────────┐
│ [①]  在 Safari 里打开这一页                      │  ← 序号
│      现在是 Safari，这一步已完成  [check]         │  ← 说明
└─────────────────────────────────────────────────┘
 20×20     16px/510 --fg      13px/400 --meta
```

| 元素 | 规格 |
|---|---|
| 行容器 | 高 56px（60px 带两行说明），底 `--surface-2`，1px `--line-subtle`，`--radius-md`，`padding: 10px 12px` |
| 序号圆 | 20×20，`--radius-pill`，底 `--surface-4`，数字 11px / 590 / `--fg-2`，右距 12px |
| 步骤标题 | 15px / 510 / `--fg` |
| 步骤说明 | 13px / 400 / `--muted`，`margin-top: 2px` |
| **已完成态** | 序号圆底 `--pos-tint`，数字 `--pos`；标题后 `check` 14px `--pos` + 说明文字 `这一步已完成`（`--pos`） |
| **强调关键词** | 按钮名（`分享`、`添加到主屏幕`、`添加`）用 `--fg` + 510，其余说明用 `--muted`。**这是让用户能在菜单里对上号的关键** |
| 当前步骤（若无法自动判断） | 不标「当前步」。**不做步骤高亮**——我们无法可靠知道用户在 Safari 的哪一步，高亮错了会让用户困惑 |

**四步的完整文案（可直接上线）**

| # | 标题 | 说明 |
|---|---|---|
| ① | `在 Safari 里打开这一页` | 现在是 Safari，这一步已完成 / **若在微信或 Chrome 中**：`先点右上角 ··· → 在 Safari 中打开` |
| ② | `点屏幕底部的分享按钮` | `方框中间一个向上箭头` |
| ③ | `在菜单里选「添加到主屏幕」` | `可能要往下滑一点才看到` |
| ④ | `点右上角「添加」` | `之后从主屏幕的图标打开，数据就不再受 7 天限制` |

> **说明文字必须写「长什么样」而不只写「叫什么」。** 分享按钮的图标是「方框 + 上箭头」，很多人不认识它，但能认出形状。第 ③ 步的「可能要往下滑一点」同理——iOS 版本不同菜单位置不同，这个提示能救掉一大半失败。

## 5. 平台分支（三种情况）

### 5.1 iOS Safari（主场景）

四步如 §4。

### 5.2 iOS 上的非 Safari 浏览器（微信 / Chrome / 夸克等）

**第一步变成「换用 Safari」**，因为 iOS 上只有 Safari 支持「添加到主屏幕」。

```
①  在 Safari 里打开这一页
   先点右上角的 ··· ，选「在 Safari 中打开」
   （微信里是右上角 ··· → 在浏览器打开）
```

- 序号 ① 圆点改 `--warn` 底 `--warn-tint`（未完成态）
- ② ③ ④ 保持但**降低视觉权重**（opacity 0.55），因为用户需要先完成 ①
- 底部多一行（13px `--warn`）：`现在这个浏览器装不了。换成 Safari 才能添加到主屏幕。`

### 5.3 已安装（standalone）

**这个 sheet 永不出现。** 设置页对应行显示完成态（见 `settings.md` §4.1）。

### 5.4 非 iOS（Android / 桌面）

不出现此 sheet。Android 走 `beforeinstallprompt` 原生安装条，桌面浏览器不需要（无 7 天清除问题）。

## 6. 数据安全说明（AC-F11-03 的落地位置）

本 sheet 只讲「安装」这一件事，**数据安全声明的主体在设置页**（`settings.md` §3）。但本 sheet 需要一句收尾，把「为什么值得装」说全：

底部次级链接：`先导出备份也行` → 点击打开设置页的导出流程，并**记住用户选择了「备份路线」**（24h 内不再弹安装引导）。

> **为什么给这条退路**：有用户就是不想装 App。强制安装 = 他会关掉提示然后忘记备份 = 7 天后数据没了。给一条「备份路线」至少能让他的数据活下来。**这一条是设计上的兜底，不是妥协。**

## 7. 无障碍

| 项 | 要求 |
|---|---|
| 角色 | `role="dialog" aria-modal="true" aria-labelledby="install-title" aria-describedby="install-desc"` |
| 焦点 | 打开时焦点移到 sheet 内的关闭按钮或第一个可聚焦元素 |
| 焦点锁定 | `Tab` 循环在 sheet 内（这是全项目**唯一**需要焦点陷阱的组件） |
| `Esc` | 关闭 |
| 关闭后 | 焦点回到触发元素（首次自动弹出时，回到主查询页的金额输入） |
| 序号 | 纯装饰，`aria-hidden="true"`；步骤用 `<ol>` 语义化，序号由 CSS 生成，读屏读「第 1 步，共 4 步」 |
| 完成标记 | `check`（lucide）14px `--pos`，`aria-hidden="true"`；语义由文字 `这一步已完成` 承担 |
| 触控 | 关闭按钮 44×44；步骤行本身不可点（是说明，不是操作），**不给它 `cursor: pointer`** |
| 减少动效 | 上滑动效 220ms → `prefers-reduced-motion` 时 0.01ms |

## 8. 视觉纪律（这个 sheet 最容易做坏）

| 禁 | 有 |
|---|---|
| 插画（手机 + 手指的矢量图） | 只用 `smartphone` 一个 24px 图标 |
| 截图模拟 iOS 界面 | 用文字描述「方框中间一个向上箭头」 |
| 红色警告三角 | `--accent-text` 的 smartphone 图标 |
| 「立即安装！」「重要！」 | `稍后再说`（明确给退路） |
| 全屏模态墙（无法关闭） | bottom sheet + 可关闭 + 24h 冷却 |
| 4 个步骤都配图标 | 只配序号圆。4 个图标会变成「图形噪音」 |
| 大红按钮 `立刻安装` | 没这按钮——**安装不是这个 App 能代为完成的动作**，Safari 里必须用户手动操作。给一个假的「安装」按钮是最严重的欺骗 |

> **最后一条是关键设计判断。** 网页无法触发 iOS 的「添加到主屏幕」。给一个「一键安装」按钮，用户点了没反应，会认为产品坏了。**正确的做法是老实给步骤**，并明确说「在主页面上点分享」——把用户引导到系统 UI，而不是假装自己能做。

# 页面：卡详情 / 编辑 `/cards/:id`

> 路由：`/cards/:id`（从卡库列表进入）
> 关联：F2（编辑）/ F6（时效 + 新鲜度）/ F4（来源可追溯）
> 基准视口：375 × 812
> 继承：`MASTER.md`。本文只写该页特有的 px 级布局

---

## 1. 这一屏承担什么

这屏是**数据可信度的产地**。用户在别的屏看到「净返 +MOP 111.00」时，能追问到「这 111 从哪来、谁说的、什么时候说的」——全部落在这屏。

三个必须承载的真实场景：
- **场景 3（优惠即将到期）**：中银澳门全币种 0% 优惠 2026-12-31 到期
- **场景 4（同卡不同结算币种费率不同）**：Amex Explorer MOP 结算 2% / HKD 结算 0%
- **场景 5（置信度差异）**：high 6 / medium 20 / low 10 / unknown 2

## 3. 顶栏（48px）

| 元素 | 规格 |
|---|---|
| 返回 | `chevron-left` 24px `--fg-2`，容器 44×44，`aria-label="返回卡库"`。有未保存改动时先弹确认 `有改动没保存，确定离开？` |

## 4. 状态带（页级，0–3 条，按优先级排序）

这一带是**所有时效与新鲜度警示的唯一集中地**。散在字段里会让用户漏看。

### 4.1 三种状态带的完整规格

**① 优惠即将到期（场景 3）**

```
┌──────────────────────────────────────────────────┐
│ [clock 16] 还剩 61 天到期                         │
│            0% 跨境手续费优惠至 2026-12-31，之后按   │
│            1.95% 计                                │
│                              去核对最新条款 ↗      │
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器 | 底 `--warn-tint`，`--radius-md`，`padding: 12px 16px`，左边 1px `--warn`（**注意：不是左侧 3px 粗条纹，是 1px 描边的一部分**） |
| 图标 | `clock` 16px `--warn` |
| 主文案 | 14px / 510 / `--warn`：`还剩 61 天到期` |
| 副文案 | 13px / 400 / `--fg-2`：`0% 跨境手续费优惠至 2026-12-31，之后按 1.95% 计` |
| 链接 | 13px `--info` + `arrow-up-right` 16px：`去核对最新条款` |
| **禁止** | 闪烁、脉冲、感叹号 `!`、红色、大写「即将到期！」、倒计时秒级跳动 |

> **它不能做得像报错。** 用黄不用红：黄 = 提醒，红 = 错误。这一条是 SPEC §8「优惠即将到期，提前 60 天警示」的落地约束——警示的目的是让用户**有时间**处理，不是让他惊慌。

**② 数据过期（>90 天，AC-F6-02）**

```
┌──────────────────────────────────────────────────┐
│ [history 16] 这张卡 124 天没核对了                 │
│              费率可能已经变了。核对过就点右边确认。    │
│                                    [确认过了]      │
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器 | 底 `--surface-2`，1px `--line`，`--radius-md`（**比到期带更轻**——数据旧不是风险事件，是日常维护） |
| 图标 | `history` 16px `--muted` |
| 主文案 | 14px / 510 / `--fg` |
| 副文案 | 13px / `--fg-2` |
| 按钮 | secondary，高 36px（命中 44px），`确认过了` |

**③ 已过期（AC-F6-04）**

```
┌──────────────────────────────────────────────────┐
│ [triangle-alert 16] 0% 优惠已于 2026-06-30 到期     │
│                    现在按 1.95% 计算。以银行最新公   │
│                    告为准。                        │
└──────────────────────────────────────────────────┘
```

容器底 `--neg-tint`，1px `--neg`，图标与主文案 `--neg`。**这是本页唯一用红的地方**——因为优惠确实失效了，计算结果已改变。

> 这对应场景里的**立桥 VISA 金卡**（`validUntil: '2026-06-30'`，已过期 4 个月，SPEC §3.3 已从预置剔除但保留在完整库）。

### 4.2 排序与叠加

| 优先级 | 状态带 | 最多 1 条 |
|---|---|---|
| 1 | 已过期（`--neg`） | 是 |
| 2 | 即将到期（`--warn`） | 是 |
| 3 | 数据过期 >90 天（`--surface-2`） | 是 |

三条可同时出现，间距 `--space-2`（8px），顶部距顶栏 16px。**顺序固定：越紧急越靠上。**

### 4.3 `daysLeft = 61` 的边界（必须实现正确）

今天是 2026-10-31，中银澳门全币种 `validUntil = 2026-12-31`：

- `daysLeft = 61` → **不满足 `<= 60`** → 状态为 `active`，**不显示到期带**
- 2026-11-01 起 `daysLeft = 60` → `expiring_soon` → 显示 `还剩 60 天到期`

**这个边界不能靠 UI 自己算日期。** `daysLeft` 与 `ValidityState` 必须由引擎给出（MASTER §11.4），UI 只负责渲染。UI 自己算会出现时区差一天的错误，而这恰好会让用户在最后一天误判。

## 5. 字段区块规格

每个区块是一组「标签-值」行，**不用卡片包裹**，用 `--space-6` 留白 + 12px 区块标题分组。

### 5.1 区块标题

| 项 | 值 |
|---|---|
| 字号 | 12px / 510 / `--muted` |
| 字距 | `var(--tracking-caps)`（0.06em） |
| 上距 | `--space-6`（24px） |
| 下距 | `--space-2`（8px） |
| 编号 | **不用 `01 · 02 ·`** |

### 5.2 通用字段行

```
  餐饮                                    10.00%   ▸
  ────────────────────────────────────────────────
  ↑ 76px 固定宽标签                         ↑ 值右对齐
```

| 元素 | 规格 |
|---|---|
| 行高 | 52px（单行）/ 64px（带副行） |
| 标签 | 13px / 400 / `--muted`，固定宽 76px，左对齐 |
| 值 | 15px / 510 / `--fg`，**右对齐**；数字 `tabular-nums` |
| 副行 | 13px / 400 / `--muted`，缩进 76px，可换行 |
| 分隔 | `border-bottom: 1px solid var(--line-subtle)`（最后一行无） |
| 可编辑 | 整行可点（`min-height: 44px`），右侧 `chevron-right` 16px `--muted` |
| 只读 | 无可点暗示，无 `chevron`，值色降为 `--fg-2` |

### 5.3 各区块字段清单

**① 基本信息**

| 字段 | 类型 | 说明 |
|---|---|---|
| 卡片名称 | 可编辑文本 | 用户可改昵称（`Card.nickname`），保留原文（含繁体/英文） |
| 发卡行 | 可编辑文本 | 预填自模板 |
| 发卡地区 | 可编辑段按钮（澳门 / 香港） | **只有两项，无美国**（SPEC §0） |
| 卡组织 | 可编辑下拉 | `维萨（Visa）` / `万事达（Mastercard）` / `银联（UnionPay）` / `美国运通（Amex）` / `吉士美（JCB）` |
| 结算币种 | 可编辑下拉 | `澳门币（MOP）` / `港元（HKD）` / `人民币（CNY）` |
| 年费 | 只读 + 说明 | `HK$2,000 · 首年免年费`（来自数据 `annualFee.waiverNote`） |

> **卡组织写中文全称 + 英文括注**，不只写 logo 或缩写。本产品不用品牌 logo（SPEC §8），文字是唯一识别方式。

**② 外币手续费（F2-AC-03 / AC-04 的关键项）**

| 字段 | 类型 | 说明 |
|---|---|---|
| 费率 | **必填** 数字输入（%） | 空则**阻止保存**（AC-F2-04），错误行 `外币手续费率没填。这一项直接决定净回报算得对不对。` |
| 默认值来源 | 只读说明 | `按香港发卡 + Visa 自动带出 1.95%。可覆盖。` |
| 分项费率（`splitRates`） | 可展开的两个数字输入 | `外币交易` / `跨域交易`。用于 BCM（外币 0.5% + 跨域 1.0%） |
| 豁免条件 | 多选 pill | `结算币种为 MOP` / `HKD` / `CNY` / `消费地区为澳门` / `中国内地` |
| 豁免截止日 | 日期选择 | 有 `validUntil` 时驱动 §4.1 状态带 |
| 来源 | `SourceLink` | 必填（SPEC §3.1：每张卡 `fxFee` 必带 `source.url`） |

**场景 4 的承载（Amex Explorer MOP 2% / HKD 0%）**

本卡 `fxFee.rate = 0.02`，无 `waivedWhen`。UI 必须让用户理解「结算币种决定费率」：

```
【外币手续费】
  费率              2.00%
  分项费率          外币 2.00% · 跨域 0.00%
  豁免条件          港元结算免收（跨境港币交易费 0%）
  说明              澳门币结算 = 2.00%（最差档）
                    港元结算   = 0.00%（最优档）
```

> **最后两行是设计增量，引擎不需要额外字段**：它只是把 `rate` 与 `waivedWhen.settlementCurrencyIn` 用自然语言并列出来。但这一行让场景 4 从"用户自己脑补"变成"UI 直接说明"。设计上做成一个只读的**推算预览行**（`--info-tint` 底），由 UI 从已有字段推导，不新增数据。

**③ 各类别返现（7 类）**

每类一行，值为费率或「未知」：

| 显示 | 条件 |
|---|---|
| `10.00%` | `kind: 'cashback'` + `rate` |
| `4 倍积分（约 2.00%）` | `kind: 'points'` + `multiplier` + 可折算时 |
| `1 倍积分（积分价值未知）` | `kind: 'points'` 但 `pointsValuation.valuePerPoint === null`（如 Amex MR） |
| `未知` | `kind: 'unknown'` ← **绝不显示 0%** |

副行显示该类的限制：`仅限云闪付/微信/支付宝渠道` / `需月实体签章满 HK$1,500` / `月上限 HK$150`。

**场景 2 的承载（中银香港 Chill 名义 10% / 上限 150）**

```
【各类别返现】
  餐饮              10.00%
                    需月实体签账 HK$1,500 · 加码月上限 HK$150
  超市              0.40%
                    无上限
```

字段行 + 副行。**「10.00%」与「月上限 HK$150」必须在同一行块内可见**，不能一个在这屏、一个在下面的上限区——那是设计让人误读的经典做法。

**④ 月度上限（`CapDefinition[]`）**

| 字段 | 类型 |
|---|---|
| 上限金额 | 必填数字 + 币种 |
| 周期 | 段按钮 `月` / `半年` / `年`（SPEC §5 `period: 'month' | 'year' | 'half_year'`） |
| 适用类别 | 多选 pill / `全类别` |
| 超额后 | `不计收益` / `按 X% 计`（`overLimitFallback`） |
| 本月已用 | **只读**（来自账本）+ 进度条 |

`本月已用` 行示意：

```
  本月已用           HK$96 · 64%
                     ▁▁▁▁▁▁▁░░░░███  剩 HK$54
                     6px 高，满宽
```

进度条规则见 MASTER §3.4：`<80%` 绿 / `80–99%` 黄 / `100%` 红 + `已用完` 文字 + 图标。

**无上限时**：本区块显示一行 `没有月度上限`（13px `--muted`），**不画条**。

**⑤ 门槛档（`ThresholdDefinition[]`）**

用**小型对照表**而非字段行，因为门槛是「条件 → 结果」的结构：

```
  月签满 HK$1,500   →   Chill 商户 10%
  月签未满           →   Chill 商户 8%
  ──────────────────────────────────
  本月已累计         HK$2,340  · 已达最高档
```

| 项 | 规格 |
|---|---|
| 左列 | `月签满 HK$1,500`，13px `--fg-2`，`tabular-nums` |
| 箭头 | `→`，13px `--muted` |
| 右列 | `Chill 商户 10%`，13px / 510 / `--fg` |
| 当前档 | 当前命中的档左侧加 3px `--accent` 竖线 + 行底 `--accent-tint`（**整行底而非条纹**） |
| 已累计行 | 分隔线下方，`本月已累计 HK$2,340 · 已达最高档`，13px `--muted` |

> **门槛与上限是相反方向**（ARCHITECTURE §12.2b）：上限 = 用得多收益减少，门槛 = 用得多收益增加。所以视觉上必须分开两个区块，不能合并成一张「规则表」——合并会让用户读不出方向。

**⑥ 数据来源（SourceList）**

```
  bochk.com ↗                        2026-10-31 核实
  信用卡产品页 · 费率与上限条款
  ────────────────────────────────────────────────
  smartcardmacao.com ↗               2026-10-31 核实
  2026-10-26 更新版 · 交叉验证
```

| 项 | 规格 |
|---|---|
| 结构 | 每项两行：`SourceLink`（域名 + 箭头）在左，`{date} 核实` 13px `--meta` 在右 |
| 第三行 | `note` 摘要，13px `--muted`，缩进 0（与第一行左对齐），`clamp 2 行` |
| 行距 | `--space-3`，分隔 `--line-subtle` |
| 目标 | `target="_blank" rel="noopener noreferrer"` |
| 空列表 | `还没有填来源`（13px `--muted`）+ `补上来源，下次核对时就不用重新搜了。` |
| 达标要求 | 每张卡至少 1 条（SPEC §3.1 数据文件约束）。0 条时顶部显示 `--warn` 提示 |

**⑦ 数据可信度（ConfidenceTag 详情形态）**

high / medium / low / unknown 四态在此区块完整展开：

| confidence | 显示 |
|---|---|
| `high` | `[check 16 --pos] 已核实` + 13px `--fg-2`：`6 项数据均有官方来源` |
| `medium` | `[check 16 --muted] 已核实` + 13px `--fg-2`：`返现结构来自官方；上限口径单一来源` |
| `low` | 黄底徽章 `待核对` + **列出具体不确定项**：`上限口径有三个来源说法不一致（年度签账额 / 年度回赠 / 每半年签账额）` |
| `unknown` | 灰底徽章 `未知` + `这个类别没有可用的费率数据。未参与排序。` |

> **`low` 必须列出「哪一项」不确定**，不能只贴标签。只贴标签等于说「我不确定但我不告诉你不确定什么」，用户无法处理这个信息。EarnMORE 的 cap 口径冲突正是典型（三个来源三种说法）。

## 6. 保存条（sticky 底部，72px）

| 项 | 规格 |
|---|---|
| 容器 | `position: sticky; bottom: 0`，高 72px，底 `--surface-1`，顶 1px `--line`，`padding: 14px 16px`（内容高 44px） |
| 主按钮 | `保存`，w-full，高 44px，`--radius-md`，底 `--accent`，字 16px / 510 `--on-accent` |
| **无改动时** | 按钮 disabled（底 `--line`，字 `--disabled`，`aria-disabled`）。**不留一个可点的「保存」让用户怀疑是不是没存上** |
| 保存中 | 文字 `保存中`（进行式）+ 左 spinner 16px，`min-width` 锁死不变宽 |
| 保存成功 | Toast `已保存`（2.5s），同时按钮回 disabled（无改动） |
| 保存失败（费率空） | 滚动到费率字段 + 该字段 `--neg` 边框 + 错误行。**不弹 toast**——就近报错 |
| iOS 键盘 | 键盘弹出时 `bottom` 改为 `calc(var(--keyboard-inset,0px) + 0px)`，避免被遮 |

> **改成即时保存行不行？** 不行。本页字段间存在依赖（改结算币种会影响外币费率的豁免判定），即时保存会让用户在中间态看到错误结果。必须给一个明确的提交点。

## 7. 删除流程（AC-F2-05）

**第一步**：顶栏 `trash-2` → 二次确认 sheet（不是原生 `confirm`，原生弹窗在 iOS 上样式不可控且无法加说明）

```
┌──────────────────────────────────────────────────┐
│  删除这张卡？                                      │
│                                                   │
│  中银香港 Chill 信用卡 会从卡库中移除。             │
│  相关的 12 条账本记录会保留，但不再参与计算。        │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │              取消                            │ │  secondary 44px
│  └─────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────┐ │
│  │              删除                            │ │  destructive 44px
│  └─────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器 | `--surface-3`，顶角 12px，底部含 `--safe-bottom` |
| 标题 | 18px / 590 / `--fg` |
| 正文 | 14px / 400 / `--fg-2`，**必须说明账本记录会怎样**（用户最担心的是「我的记录会不会一起没了」） |
| 取消按钮 | secondary 样式，高 44px，**在上**（拇指更容易够到安全选项） |
| 删除按钮 | `透明底 + 1px --neg + --neg 文字`，高 44px。**不用红填充**——红填充会把破坏性操作做成主操作 |
| 账本为空时 | 正文改为 `中银香港 Chill 信用卡 会从卡库中移除。没有关联的账本记录。` |

> 停用（`active: false`）不在本页提供。SPEC 未列此功能，MVP 不做。**不要因为数据模型有 `active` 字段就加这个 UI** —— SPEC 是契约，未列出的功能一律不做。

## 8. 空 / 错误状态

| 场景 | 表现 |
|---|---|
| 新建卡（无 id） | 标题 `新卡片`；所有字段空；费率字段预填默认值（按 `发卡地区 + 卡组织` 二维带出，AC-F2-03）；顶部无状态带 |
| 卡不存在（id 无效） | 居中：`这张卡不在了`（18px/590）+ `可能已经被删除了。`（14px `--fg-2`）+ 主按钮 `回卡库` |
| 外币费率空 | 该字段 `--neg` 边框 + 13px 错误行 `外币手续费率没填。这一项直接决定净回报算得对不对。`；保存按钮保持 enabled（让用户点了才知道哪错了），点了则滚到该字段 |
| 豁免截止日是过去 | 字段下方 13px `--neg`：`这个日期已经过了。豁免已失效。` 并在状态带显示「已过期」 |
| 来源为空 | 区块显示 `还没有填来源` + 引导，不阻止保存（但顶部加 `--warn` 一行 `这张卡没有来源，可信度只能标 low`） |
